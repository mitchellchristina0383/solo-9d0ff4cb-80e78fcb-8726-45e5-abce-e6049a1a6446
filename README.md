# 流式线性回归标定（Flask + SQLite，CPU）

面向小内存机器的校准训练网页：上传两列 CSV（实测值 x、参考值 y），按原行序分组，
逐段读入、累积梯度，每组只做一次带动量更新；随时可暂停，重启后可调小读取上限继续，
跑完结果与不中断训练一致。标定数据分批到齐时，可在已完成作业上上传**无表头的两列
增量 CSV**，一键另建同配置续训作业，旧样本在前、新样本在后，旧数据的完整组零重算。

## 快速开始

```bash
docker compose up --build -d
# 打开 http://localhost:8000
docker compose logs -f            # 查看运行日志
docker compose down               # 停止（数据在 calibration-data 卷里保留）
```

数据卷 `calibration-data` 挂到容器 `/data`：SQLite 库与上传的 CSV 都在其中，
重新 `up` 后可以直接在网页上“继续训练”。

## 使用流程

1. 首页上传 CSV，填每组样本数、单次读入行数上限、学习率、动量、初始 w/b。
   表头可有可无（`x,y`、`实测值,参考值` 均可）；空行跳过。
2. 训练详情页可设“读完 N 段后暂停”或“完成 N 组更新后暂停”（留空则跑到结束），点开始。
   “段”是单次读入上限对应的块，“组”对应一次参数更新。
3. 需要主动暂停时点“主动暂停”：当前读取段结束后立刻落盘暂停，**下次从下一行继续**。
4. 暂停状态可把“单次读入行数上限”改小（例如 200 → 3）再“继续训练”。
5. 页面实时显示更新次数、已计入样本数、组内已读未更新行数、w/b、动量 v_w/v_b、
   峰值驻留行数与进程峰值 RSS，下方是可复核的逐次更新审计表。

## 算法与内存

模型 `ŷ = w·x + b`，平方误差。每组连续 `group_size` 行（末组不足也更新）：

```
g = mean(2·(w·x + b − y)·[x, 1])
v = momentum·v − lr·g
w, b += v
```

每次读取最多把 `chunk_limit` 行放进临时列表，逐行累加进组内梯度/损失，随即丢弃该列表。
峰值驻留样本数为 `min(chunk_limit, group_size)`，与文件大小无关；模型状态只有几个 double。
每行读取有 1 MiB 硬上限，畸形超长行会报错而不是吃光内存。

## 断点与一致性

SQLite 以 WAL + `synchronous=FULL` 运行；参数、动量、已计入样本数、更新次数和
组内累加器都在同一行。两种提交：

* **更新提交**（每组一次）：参数、动量、`samples_done`、`updates_done` 与一条审计记录
  在同一事务里写入 —— 一次更新要么完整生效，要么完全不生效。
* **暂停提交**（仅主动暂停，发生在读取段边界）：把组内部分梯度/损失与文件偏移
  `next_offset` 一并写入 —— 主动暂停后从下一行继续，**不重读任何行**。

意外退出不会执行暂停提交，因此从最近一次组边界重启：已计入的组绝不重读，
只有未完成的那一组重读一次（≤ 1 组）。启动时 `recover()` 把残留的 `running`
标成“意外中断”，网页上点“继续训练”即可。

浮点一致性：每行按文件顺序逐行累加进运行和，SQLite 存 IEEE-754 double，
所以读取段大小变化、暂停次数多少都不会改变舍入，续训与不中断结果逐位相同。

## 增量续训（分批到齐的数据）

在一个**已完成**作业的详情页上传无表头的两列增量 CSV，系统会另建一个同配置续训作业：

1. 增量文件先做整文件流式校验：必须无表头、每行两列有限数值、空行跳过、单行 1 MiB 上限，
   首行非数值直接按“含表头”拒绝。
2. 按“旧样本在前、新样本在后”生成合并数据文件：两段均按 1 MiB 块原样拷贝，
   不把任何行读进内存；旧段字节与原文件逐字节一致。旧段末尾无换行时在接缝补一个 `\n`，
   避免两行粘连（`seam_padding` 记录是否补过）；增量开头的 UTF-8 BOM 会跳过。
3. **旧末组已满**（父作业行数是每组样本数的整数倍）：父作业的全部组记录与训练进度
   直接复制到新作业，参数/动量从父作业终态继续，新作业从增量第一行开始读，
   这些沿用组的梯度完全不重算。
4. **旧末组未满**：只沿用前面的完整组，丢弃未满末组的更新；新作业恢复到该组
   *开始之前*的参数与动量（取自最后一条沿用审计记录），读偏移指向旧末组第一行，
   把这组旧样本与新增样本接着按原 `group_size` 重新分组。
5. 合并文件、复制的审计记录与续训断点在**同一事务**提交；任何一步校验或保存失败，
   半成品合并文件被删除、新作业不出现，并在页面说明原因，原作业照常可查。

逐位一致性：合并文件的旧段与原文件字节相同，沿用组的梯度/参数/动量数值直接复制，
未满末组回退后的重算顺序与“合并后从头训练”完全一致，因此最终参数、动量与**每一组**
审计数值（梯度、均方误差、v、w/b）都与合并数据不中断训练逐位相同。

内存上界不变：合并是块级拷贝，续训训练时仍按 `chunk_limit` 分段读入，
峰值驻留样本数只取决于 `chunk_limit`，与新旧样本总数无关；沿用组不产生任何读取和梯度计算。

血缘与防分叉：续训作业通过 `parent_run_id` 指向原作业，详情页与首页都展示沿用了多少组、
新增多少行；每个原作业最多创建一个续训作业（防止同一份数据产生分叉），续训链路可逐级追溯。
续训作业详情页的一致性审计会把接缝处的换行视为合法空行，并对沿用组之后的新组重放校验。

CLI 等价入口（脚本/CI 用）：

```bash
python3 -m trainer.cli continue --db /data/trainer.sqlite3 --parent-id 1 \
    --parent-data /data/uploads/parent.csv --incr /tmp/new-batch.csv \
    --upload-dir /data/uploads
```

增量续训的端到端对照（两种末组形态，逐位对比合并后从头训练）：

```bash
python3 scripts/verify_continuation.py --work /tmp/v-cont-full    --tail full
python3 scripts/verify_continuation.py --work /tmp/v-cont-partial --tail partial
```

实测输出（父 1,000 行 / 增量 537 行 / 每组 200 / 每段 16，学习率 2e-5）：

| 末组形态 | 沿用组 | 续训会话新算组 | 最终 w/b/v 与参考 | 逐组数值 | 审计 |
| --- | --- | --- | --- | --- | --- |
| `full`（父行数整除组大小） | 全部父组 | 仅新增样本产生的组 | 逐位相同 | 逐位相同 | 通过 |
| `partial`（父末组 66 行未满） | 仅完整组，末组回退 | 从旧末组起点重算 | 逐位相同 | 逐位相同 | 通过 |

两种形态都校验：续训会话不对任何沿用组计算梯度、`peak_rows_held ≤ chunk_limit`、
父作业在续建前后状态与数值完全不变。

大规模内存实测（父 2,000,000 行 + 增量 500,000 行，合并 250 万行 / 每组 100,000 / 每段 500）：
续训作业峰值驻留 500 行、进程峰值 RSS ≈ 20.6 MB，与只跑父作业时基本相同；
20 个完整父组零重算，续训会话只新算 5 个组（约 1.7 秒），最终参数与合并后
250 万行从头参考训练逐位一致。

两种中断的端到端对照（生成数据后各跑一次，结果逐位对比不中断训练）：

```bash
python3 scripts/gen_data.py /tmp/cal.csv -n 50000
python3 scripts/verify.py --mode pause --data /tmp/cal.csv --work /tmp/v-pause
python3 scripts/verify.py --mode kill  --data /tmp/cal.csv --work /tmp/v-kill
```

实测输出（50,000 行 / 每组 2,000 / 每段 100）：

| 模式 | 中断点 | 续训后更新/样本 | 与不中断最大差 | 审计 |
| --- | --- | --- | --- | --- |
| `none` | — | 25 / 50,000 | 0（逐位相同） | 通过 |
| `pause` | 2 组 + 200 行部分组已落盘 | 25 / 50,000 | 0（逐位相同） | 通过 |
| `kill` | 2 组已提交，组中 `os._exit(9)`；重启后段上限 100→1 | 25 / 50,000 | 0（逐位相同） | 通过 |

`pause` 校验“部分组累加器已持久化、偏移恰好对应只读一次的行数”；
`kill` 校验“只剩整组边界、未完成组回退、最多重读一组”。

内存实测（2,000,000 行 / 38 MB CSV / 每组 100,000 / 每段 500）：
子进程峰值 RSS ≈ 20.5 MB，与 50,000 行时的 ≈ 20 MB 基本相同；
数据库里记录的 `peak_rows_held = 500`。纯 Python 解析约 29 万行/秒（预热后），
200 万行整轮约 20 秒。
